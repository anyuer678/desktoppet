版本：0.1.0803.01（设计基线，内容核验至 v1.0 现状）

配套文档：角色包规范 / API设计 / 开发规范

---

## 1. 项目定位

桌面角色平台，而非单个桌宠。

- 角色 = 资源包（`.pet`）
- 核心引擎（状态/事件/动画/渲染）与角色完全解耦
- 角色由用户上传或制作，引擎不关心角色具体形象

示例：兔兔 / 水墨小人 / 机器人 → 都只是换资源包，核心代码不动。

## 3. 进程模型

```text
┌─────────────────────────────────────────────────────┐
│                   Electron Main                     │
│  ┌───────────┬───────────────┬───────────────────┐  │
│  │ 窗口管理    │ 角色系统(加载)  │ 设置存储(JSON)    │  │
│  │ (透明置顶   │ 校验/构建状态表 │ 开机启动/目录     │  │
│  │  多窗口)   │               │ 位置/尺寸/透明度   │  │
│  ├───────────┴───────────────┴───────────────────┤  │
│  │ 已实现: 事件总线 / 插件宿主 / 系统监控            │  │
│  └───────────────────────────────────────────────┘  │
│                          ▲                          │
│                IPC (contextBridge 白名单)            │
│                          ▲                          │
└──────────────────────────┼──────────────────────────┘
                           │
┌──────────────────────────┼──────────────────────────┐
│              Renderer (React, 同一 bundle)          │
│                                                      │
│   ┌─ 置顶透明的桌宠窗口 ─┐     ┌─ 控制中心窗口 ──┐    │
│   │ 动画播放器           │     │ Dashboard/角色  │    │
│   │ 状态机(动画选择)     │     │ 动画/事件/设置  │    │
│   │ CSS3D 帧/模板渲染    │     │ (shadcn/ui)    │    │
│   └─────────────────────┘     └───────────────┘    │
│     单入口 bundle + hash 路由 (#/pet / #/center)     │
└─────────────────────────────────────────────────────┘
```

约定：

- 渲染进程无 Node 权限：`contextIsolation: true`、`sandbox`、关闭 `nodeIntegration`。
- 渲染进程只能通过 `preload` 暴露的白名单 API 与主进程通信。
- 插件的存在逻辑、文件读写、全局快捷键都在主进程，渲染进程只有 UI。
- 两个窗口加载同一 renderer 产物，通过 `location.hash` 区分挂载点（pet / center），减少 dev 复杂度。
- 事件总线 / 插件宿主 / 系统监控均已实现：`src/main/event/`（eventCenter / sourceHub / eventHistory / clipboard 等）、`src/main/plugin/`（pluginHost，示例插件在顶层 `plugins/sample/`）、`src/main/monitor/`（systemMonitor / battery）。

## 3.1 资源提供：pet:// 协议

渲染进程禁止 `file://` 访问磁盘，角色素材统一走自定义协议：

```text
pet://<角色id>/<相对路径>
   → 主进程 protocol.handle 按 host=角色id 映射到 characters/<id>/<相对路径>
```

- 协议在 app ready 前注册：`standard + secure + supportFetchAPI`。
- 映射必须做路径校验（禁止越出角色包目录）。
- `<img>`、CSS、动画帧加载全部走此协议；v0.1 开发期角色包为目录形式。
- 注意：协议注册为 `standard` 后首段是 **host** 而非 path（`pet://rabbit/avatar.png`）。

## 4. 数据流

### 目标架构（完整事件驱动）

```text
事件源(插件 / 系统监控 / API / 用户)
   ↓ 标准事件 { type, source, priority, duration, data }
事件中心(去重 / 优先级 / 聚合)
   ↓ 当前有效事件集
状态决策(主状态 + 环境因子 → 状态对象)
   ↓ 状态对象
动画管理器(选择状态动画, 缺帧回退)
   ↓ 动画帧 / 模板效果
渲染层(帧绘制 / CSS 变换)
```

### v0.1 切片

v0.1 **不实现**事件系统，但遵循同一方向：渲染层只吃"状态 → 动画"，
状态暂时恒定（idle），后续 v0.2 只需替换状态来源，无需改渲染层。

```
角色包(config.json + 素材)
   → 角色加载器(校验 / 构建状态动画表)
   → 动画管理器(状态=idle → 序列帧 或 空闲模板)
   → 桌宠渲染组件(透明窗口)

用户交互(单击 / 双击 / 右键 / 拖动)
   → IPC → 主进程(窗口 / 设置 / 角色切换)
```

## 6. IPC 契约概览

详细见 `docs/API设计.md`。原则：

- 所有 channel 以域名为前缀：`character:*` / `window:*` / `settings:*`。
- 渲染进程只读"配置视图数据"，写入必须过主进程校验。
- 事件推送用 `webContents.send` 单向，配合 `invoke/handle` 请求-响应。
- 类型定义共享一份（`src/shared`），主进程与渲染层共用，保证契约闭环。

## 7. 安全与隔离

- `contextIsolation: true`，`sandbox: true`，`nodeIntegration: false`。
- preload 仅暴露固定 API 集合，不暴露 `ipcRenderer` 本身。
- 角色包 `config.json` 严格校验：非法路径、类型错误一律拒绝并回退内置占位 UI。
- 插件（v0.3+）只能在主进程声明事件，不暴露文件系统/窗口权限。
- 日志打到 userData/logs（开发模式 userData 取 package.json 的 name `desktop-pet` → `%APPDATA%/desktop-pet/logs`；打包正式版 userData 按 productName 为 `DesktopPet` → `%APPDATA%/DesktopPet/logs`），不把内部路径上传到 UI。

## 8. 关键决策记录（ADR）

| 决策 | 理由 | 备注 |
| --- | --- | --- |
| Electron 做正式路线（非 Tauri/ Qt） | 透明窗口、系统读取、插件、AI 生态需求匹配度最高 | 见需求阶段结论 |
| 渲染进程无 Node 权限 | 透明窗口安全性与隔离 | 控制台不能拿到 disk 路径 |
| 角色素材走 `pet://` 自定义协议 | 渲染层无 `file://` 权限，且可做路径白名单 | 见 3.1 节 |
| 单入口 bundle + hash 路由 | 多窗口共用一套依赖与 UI 基件 | pet 窗口 `#/pet`，中心 `#/center` |
| 透明窗口不启用系统缩放 | Windows 透明窗口无系统缩放边框，且 `transparent` 与系统 resize 冲突 | 尺寸在控制中心调，主进程 `setSize` |
| 动画第一期只做 idle | 先验证角色资源体系，缩小 v0.1 范围 | 后续 happy/sleep 入 v0.2 |
| 状态=「主状态 + 环境」而非枚举组合 | 避免 `Work×Night×CPU…` 组合爆炸 | 状态机只输出主状态，叠加层为修饰 |
| 角色包 config 现在定死 | 角色/动画/插件三系统都依赖它 | 见角色包规范.md |

## 10. 陪伴统计（v0.5 起已实现）

桌面宠物是陪伴型应用，长期的"共处数据"是有价值的功能面（用户时间感知）。v0.5 起已完整落地（在线时长/状态分布/互动次数/热力图/24h 分布/streak/CSV 导出/按年 Excel/成就里程碑均可用）：

| 环节 | 实现 |
| --- | --- |
| 记录范围 | 每日在线时长（按状态细分：idle/focus/sleep/happy/warning）、24 小时分段时长（hours[24]）、事件次数（CPU 高/低电量/日程触发等）、互动次数（点击/拖动/说话）、活跃天数 |
| 记录方式 | 主进程常驻统计器：事件 tick 按 4s 粒度累加当前状态时长（写入当日 hours 对应小时段）；渲染层互动通过 `pet:interact` 上报主进程计数；日程/事件触发时计数 |
| 存储 | `userData/stats/` 按天文件（`YYYY-MM-DD.json`），JSON 写入（SQLite 仍预留），重启保留；旧文件缺 `hours` 字段加载时补零 |
| 展示 | 控制中心首页「陪伴统计」卡片（今日/本周时长、状态分布、互动、连续陪伴 streak；15s 自动刷新）+「统计」页签（日期区间查询与每日时长/状态堆叠/事件趋势/互动次数图，纯 CSS 无三方库）+ 月度/年度热力图（4 档配色日历格、可删单日）、24 小时时段分布、年度汇总卡（总陪伴/活跃天/日均/最活跃日/streak）、成就与里程碑卡（等级进度 + 徽章网格）、数据管理（CSV 导出/清空） |
| 约束 | 只读本地统计，不联网；数值基于已存在的事件/状态数据，不引入新采样 |
