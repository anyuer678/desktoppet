# DesktopPet 部署说明

版本：0.4.0804.01（内容核验至 v1.0 现状）
配套文档：架构设计 / 角色包规范 / API设计 / 使用说明

---

## 1. 环境要求

| 项 | 最低版本 | 备注 |
| --- | --- | --- |
| Node.js | 18+ | 推荐 20 LTS |
| npm | 9+ | 随 Node 附带 |
| 操作系统 | Windows 10/11 | 当前仅验证 Windows |

> 首次安装依赖前，`.npmrc` 已配置 npmmirror 镜像加速 Electron 二进制下载。如遇网络问题，可设置代理 `npm config set proxy http://127.0.0.1:7890`。

---

## 2. 依赖安装

在项目根目录执行：

```bash
npm install
```

安装完成后目录生成 `node_modules/`。该目录已在 `.gitignore` 中忽略，不入库。

---

## 3. 开发模式运行

```bash
npm run dev
```

等价于 `electron-vite dev`：

- 启动 Vite 开发服务器（HMR 热更新）
- 自动拉起 Electron 主进程
- 渲染层改动即时生效，主进程改动自动重启

也可使用一键脚本：

```bat
启动.bat
```

---

## 4. 类型检查与单元测试

### 类型检查

```bash
npm run typecheck
```

分别对 `tsconfig.node.json`（主进程/preload/shared）与 `tsconfig.web.json`（渲染层）执行 `tsc --noEmit`。

### 单元测试

```bash
npm test
```

执行 `vitest run`，覆盖：

- `src/main/character/` — 角色读取/编辑/导入导出
- `src/main/event/` — 事件中心决策
- `src/main/monitor/` — 系统监控采样
- `src/main/perf/` — 性能汇总
- `src/main/storage/` — 设置存储
- `src/main/window/` — 窗口位置校验
- `src/renderer/src/pet/` — 动画状态/点击穿透/叠加层
- `src/shared/` — 语音时段判定

### 一键自检

```bat
自检.bat
```

依次执行类型检查 + 单元测试，全部通过才输出 `All checks passed.`。

## 5. 生产构建

```bash
npm run build
```

等价于 `electron-vite build`，输出至 `out/`：

```text
out/
├── main/         主进程编译产物（index.js）
```

`out/` 已在 `.gitignore` 中忽略。

### 构建验证

```bat
构建验证.bat
```

依次执行：类型检查 → 单元测试 → 生产构建。任一步失败即终止并提示 `FAILED`。

### 预览构建产物

```bash
npm run preview
```

以生产模式加载 `out/` 产物启动 Electron，用于验证构建结果与开发态行为一致。

## 6. 打包发布

`electron-builder` 已配置完毕：`package.json` 的 devDependencies 含 `electron-builder@^26.15.3`，仓库根目录的 `electron-builder.yml` 提供完整打包配置：

- `appId`：`com.desktoppet.app`
- `productName`：`DesktopPet`
- 输出目录：`release/`（已在 `.gitignore` 中忽略）
- `extraResources`：随包携带 `characters/` 与 `plugins/`
- `win` 目标：nsis 安装包，`oneClick: false`（安装时可选择安装目录），创建桌面快捷方式 `DesktopPet`

打包命令：

```bash
npx electron-builder --win
```

产物输出至 `release/`（含 `win-unpacked/` 免安装目录与 nsis 安装包）。正式版发布时 `release/` 内需包含：安装包、更新日志、README、使用说明、源代码备份（见《开发规范》第三节）。

## 7. 角色包部署

### 角色仓库位置

开发期：`<项目根>/characters/<角色 id>/`

生产期（打包后）：角色包随 `characters/` 一起打入安装包。用户导入的角色写入 userData 目录（由主进程 `app.getPath('userData')` 解析）。

### 角色包结构

```text
characters/rabbit/
├── config.json     角色配置（必需）
├── avatar.png      主图（透明底 PNG，必需）
├── preview.jpg     预览图（可选）
└── <其他序列帧>     按状态命名，参考角色包规范
```

### 导入与导出

- 控制中心「角色」页 → 「导入角色包」选择 `.pet`/`.zip` 文件
- 角色卡片「导出」按钮 → 生成 `<id>-v<version>.pet` 压缩包
- 角色卡片「删除」按钮 → 确认后移除（删除当前激活角色时自动回退到剩余第一个）

详见 `docs/角色包规范.md`。

## 8. 配置与数据目录

### 设置文件

路径：`<userData>/settings.json`

包含：`activeCharacterId`、`size`、`opacity`、`position`、`autoLaunch` 等。

- 主进程启动时加载，变更时防抖 300ms 写盘
- 大小钳制 96~512，透明度钳制 0.3~1
- 位置启动时校验，超出所有显示器工作区自动回落主屏

### userData 路径（Windows）

userData 目录由主进程 `app.getPath('userData')` 解析，实际路径取决于运行模式：

- 开发模式（`npm run dev`）：应用名取 `package.json` 的 `name`（`desktop-pet`），路径为：

  ```text
  C:\Users\<用户名>\AppData\Roaming\desktop-pet\
  ```

- 打包正式版：electron-builder 以 `productName`（`DesktopPet`）覆盖应用名，路径为：

  ```text
  C:\Users\<用户名>\AppData\Roaming\DesktopPet\
  ```

### 单实例锁

应用启动调用 `app.requestSingleInstanceLock()`，重复启动直接退出并唤出已运行实例的控制中心。

## 9. 故障排查

| 现象 | 排查方向 |
| --- | --- |
| 启动报 `net\disk_cache Unable to move the cache` | 已通过 `disable-gpu-shader-disk-cache` 修复，若复现检查是否有残留进程占用 userData |
| 角色图片加载 404 | 检查 `pet://<id>/<path>` 协议，id 与角色目录名一致，path 不含 `..` |
| 点击穿透失效 | 检查图片 alpha 阈值（当前 32），位图未就绪时按内容矩形兜底 |
| 窗口位置丢失 | `display-metrics-changed` 触发 `ensurePetPosition`，校验窗口与显示器工作区交集 |
| 设置调节不生效 | 确认走 `settings:set` / `window:setSize` / `window:setOpacity` 入口，渲染层订阅 `pet:settings-changed` |
