# v0.8 事件推送 API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 桌宠启动本地 HTTP 服务（127.0.0.1 随机端口），第三方程序用 Bearer token POST `/api/event` 推送事件 → 桌宠气泡转达 + 事件中心状态变化 + 计入统计；控制中心新增「推送」页签管理服务（启用/重置 token/测试）。

**Architecture:** 新增 `pushApi.json` 配置（独立 store，含 enabled/token）；纯函数校验（`pushApi.ts`：parseEventBody / isAuthorized / generateToken）；HTTP 服务层（`httpService.ts`：createServer + 路由 + 401/400/413/404/405/503）；主进程接入（`index.ts`：启动/关闭、onPushEvent 注入事件中心 + 气泡 + 统计）；IPC 四通道（get/setEnabled/resetToken/test）+ `push:fired` 事件；CenterApp 新页签；PetApp 气泡。

**Tech Stack:** Electron + TypeScript + vitest + Node 内置 `http`（无新依赖）。

## Global Constraints

- 零新增依赖（spec §1）。
- 只绑 `127.0.0.1`、不联网（spec §1）。
- 认证 `Authorization: Bearer <32hex token>`；body ≤8KB（spec §2/§4）。
- 事件默认 type `notice`（focus）；气泡 8s；`countEvent('push')`（spec §5）。
- 服务启动失败仅记日志不影响主程序；退出时幂等关闭（spec §4/§5）。
- 版本 `v0.8.0806.01`；测试 `npm test`、typecheck `npm run typecheck`、build `npm run build`。
- 文档每次构建后同步：CHANGELOG / 使用说明 / API 设计 / 架构设计 §9 路线图。

### Task 3: HTTP 服务层（httpService.ts）

**Files:**
- Create: `src/main/push/httpService.ts`
- Test: `src/main/push/httpService.test.ts`

**Interfaces:**
- Produces:
  - `PushServerDeps { getConfig(): PushApiConfig; onPushEvent(body: PushEventBody): void; log(level: string, ...args: unknown[]): void }`
  - `startPushHttpService(deps: PushServerDeps): Promise<{ port: number; close(): Promise<void> }>`
    - `http.createServer` 监听 `127.0.0.1`，`listen(0)` 取实际端口。
    - 路由：`POST /api/event` → 处理；其他路径 404；方法非 POST 405；`deps.getConfig().enabled === false` → 503。
    - 读 body 上限 8KB（超限 413），解析 JSON 失败 400。
    - 认证：`isAuthorized(req.headers.authorization, cfg.token)` 失败 401。
    - `parseEventBody` 失败 400；成功 → `deps.onPushEvent(body)` → 200 `{ ok: true }`。
    - 异常 try/catch 包裹 → 500 + 日志，不崩。
    - `close()` 幂等（已关闭返回）。
- Consumes: `PushApiConfig`、`PushEventBody`、`parseEventBody`、`isAuthorized`（Task 1/2）。

**Steps:**
1. 新建 `src/main/push/httpService.ts`：核心路由处理抽为 `handlePushRequest(deps, req, bodyBuffer): number + 响应` 思路，请求级 try/catch；`startPushHttpService` 负责 createServer/listen/error 事件（error 记日志）。
2. 新建 `src/main/push/httpService.test.ts`：集成测试用 `startPushHttpService` 真实 listen(0) + `fetch`/`http.request` 请求：
   - 200：合法 body + 正确 Bearer → onPushEvent 被调用且参数正确。
   - 401：缺 header / 错 token。
   - 400：body 非 JSON / 缺 title。
   - 404：路径不对；405：GET。
   - 413：>8KB body。
   - 503：config enabled=false。
   - close() 幂等，close 后连接失败。
3. `npm test -- httpService` 通过；typecheck。

**Interfaces:**
- Produces（模块内）:
  - `let pushApiCfg: PushApiConfig`（whenReady 加载 `userData/pushApi.json`）
  - `let pushServer: { port: number; close(): Promise<void> } | null`
  - `pushApiConfigPath()`、`loadPushApiCfg()`、`savePushApiCfg()`（写文件）
  - `ensureToken()`：token 空时生成并保存
  - `onPushEvent(body)`：`countEvent('push')` + 注入事件中心 `{ source: 'push:'+randId, type: body.type ?? 'notice', priority: 50, durationMs: 8000, occurredAt: now }` + `notifyPet('push:fired', { title, body: message })` + 触发一次状态刷新（仿 fireSchedule）+ `notifyCenter('pet:events', snapshot)`
  - `startPushApiService()`：`ensureToken()` → `startPushHttpService` → 记录 port；失败仅 log
  - `stopPushApiService()`：close 幂等 + 置 null
- IPC handlers（whenReady 注册）:
  - `pushApi:get` → `{ ok: true, info: { enabled: cfg.enabled, port: pushServer?.port ?? 0, token: cfg.token } }`
  - `pushApi:setEnabled`（boolean）→ 启：`startPushApiService()`；停：`stopPushApiService()`；保存 cfg → `{ ok: true }`
  - `pushApi:resetToken` → `ensureToken(force=true)`（新随机 token 保存）→ `{ ok: true, token }`
  - `pushApi:test` → `onPushEvent({ title: '测试推送', message: '桌宠收到啦', type: 'complete' })` → `{ ok: true }`
- preload 暴露 `pushApi`: `get()` / `setEnabled(enabled)` / `resetToken()` / `test()`；事件 `onPushFired(handler)`。
- 生命周期：`app.whenReady()` 内 `startPushApiService()`；`app.on('will-quit')` 调 `stopPushApiService()`。
- Consumes: Task 1/2/3 全部导出。

**Steps:**
1. 在 `index.ts` 顶部 import：`loadPushApiConfig/savePushApiConfig/validatePushApiConfig/DEFAULT_PUSH_API_CONFIG`、`parseEventBody`（仅测试用可不引）、`startPushHttpService`、`PushApiConfig`。
2. 声明模块级状态（pushApiCfg/pushServer）+ 辅助函数（路径、load/save、ensureToken、onPushEvent、start/stop）。
3. whenReady 中：`pushApiCfg = loadPushApiConfig(pushApiConfigPath())`；`startPushApiService()`；注册 4 个 IPC handler。
4. `app.on('will-quit')` 中追加 `stopPushApiService()`。
5. preload 暴露 `pushApi.*` 与 `events.onPushFired`；index.d.ts 同步。
